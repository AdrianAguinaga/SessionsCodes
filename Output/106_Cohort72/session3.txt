    <p style="margin: 0 0 8px 0; color: #0d2c4f;"><strong>💡 Key Concept &mdash; POST vs. PUT</strong></p>
    <p style="margin: 0; color: #1f2d3d; font-size: 0.95rem;"><strong>POST</strong> is for <em>new</em> things. <strong>PUT</strong> is for <em>existing</em> things &mdash; you MUST have an ID to use PUT. And remember: you cannot simply "send an object" across the internet. It must be <strong>serialized</strong> into a JSON string first.</p>
</div>
<h2 style="color: #0d2c4f; border-bottom: 3px solid #d23939; padding-bottom: 6px; font-size: 1.35rem;">📚 What We'll Build Today</h2>
<p style="color: #1f2d3d; margin-bottom: 16px;">Today the Task Manager gains real <strong>persistence</strong>: tasks you create will survive a page refresh. Click each part to expand the details.</p>
<details style="background-color: #ffffff; border-radius: 10px; padding: 14px 18px; margin-bottom: 10px; border: 1px solid #dde5ec;">
    <summary style="cursor: pointer; color: #0d2c4f; font-size: 1.05rem;"><strong>Part 1 &middot; The Data Journey (Theory)</strong> &mdash; Serialization &amp; the "shipping label"</summary>
    <p style="margin: 12px 0 6px 0; color: #1f2d3d;"><strong>Serialization</strong> converts a living object (in RAM) into a text string (JSON) so it can travel through the wire. The <strong>Content-Type</strong> header is the "shipping label" on the packet telling the server: "This string is actually JSON data &mdash; please parse it."</p>
    <pre style="background-color: #0d2c4f; color: #e8f0f8; border-radius: 8px; padding: 16px; font-size: 0.8rem; overflow-x: auto;">🔄 THE DATA SERIALIZATION JOURNEY

  Browser (Client)                                          Cloud (Azure Server)
  ----------------                                          --------------------
1. JS Object (RAM)
   { title: "Work" }
         │
         ▼
2. JSON.stringify() ─── [SERIALIZATION]
         │
         ▼
3. JSON String ────── [ TRANSPORT ] ──▶  4. Receive String
   '{"title":"Work"}'    (HTTP POST)              │
                                                  ▼
                                            5. JSON.parse()
                                                  │
                                                  ▼
   Receipt (201 Created) ◀── [ RESPONSE ] ── 6. JS Object + ID
   { id: 99, ... }                           { id: 99, title: "Work" }</pre>
</details>
<details style="background-color: #ffffff; border-radius: 10px; padding: 14px 18px; margin-bottom: 10px; border: 1px solid #dde5ec;">
    <summary style="cursor: pointer; color: #0d2c4f; font-size: 1.05rem;"><strong>Part 2 &middot; Implementing POST</strong> &mdash; Refactoring <code>saveTask()</code> into a real network request</summary>
    <p style="margin: 12px 0 6px 0; color: #1f2d3d;">In Session 2, <code>saveTask()</code> was just a local echo. Now it sends the task to the server for real:</p>
    <pre style="background-color: #0d2c4f; color: #e8f0f8; border-radius: 8px; padding: 16px; font-size: 0.85rem; overflow-x: auto;">$.ajax({
    type: "POST",                    // HTTP Verb: CREATE
    url: API,
    data: JSON.stringify(data),      // Convert to String
    contentType: "application/json", // The "Shipping Label"

    success: function(created){
        displayTask(created);  // Use the SERVER'S version!
        clearForm();
    },
    error: function(err){
        console.error("POST error:", err.responseText || err);
        alert("Task could not be saved.");
    }
});</pre>
    <p style="margin: 12px 0 6px 0; color: #1f2d3d;"><strong>🤔 Crucial question:</strong> Why do we pass <code>created</code> to <code>displayTask()</code> instead of <code>data</code>? Because <code>created</code> is the <strong>"receipt" from the server</strong> &mdash; it contains the ID the server generated (e.g., <code>id: 104</code>). We'll need that ID later to delete or edit the task.</p>
</details>
<details style="background-color: #ffffff; border-radius: 10px; padding: 14px 18px; margin-bottom: 10px; border: 1px solid #dde5ec;">
    <summary style="cursor: pointer; color: #0d2c4f; font-size: 1.05rem;"><strong>Part 3 &middot; Analyzing Server Logic</strong> &mdash; Thinking like a backend developer</summary>
    <p style="margin: 12px 0 6px 0; color: #1f2d3d;">We switch roles to "Backend Developer" and walk through what happens inside the Azure Function when a POST arrives:</p>
    <ul style="color: #1f2d3d; margin: 6px 0;">
        <li style="margin-bottom: 4px;"><strong>Validation check:</strong> if there's no <code>title</code>, the server responds <code>400 Bad Request</code>.</li>
        <li style="margin-bottom: 4px;"><strong>ID generation:</strong> the server assigns the ID &mdash; the client cannot guess this number.</li>
        <li style="margin-bottom: 4px;"><strong>Storage:</strong> <code>DB.unshift(created)</code> adds the task to the <em>top</em> of the list.</li>
        <li><strong>Response:</strong> the server returns <code>201 Created</code> with the complete object.</li>
    </ul>
</details>
<details style="background-color: #ffffff; border-radius: 10px; padding: 14px 18px; margin-bottom: 28px; border: 1px solid #dde5ec;">
    <summary style="cursor: pointer; color: #0d2c4f; font-size: 1.05rem;"><strong>Part 4 &middot; Updating Data (PUT)</strong> &mdash; "Console Hacking" activity</summary>

        <li style="margin-bottom: 4px;">Open the Network tab or Console and find the <strong>ID</strong> of that task (e.g., <code>1</code>).</li>
